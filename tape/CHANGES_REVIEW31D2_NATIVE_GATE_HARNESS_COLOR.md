## Root causes and corrections

### 1. Legacy dd mocks did not implement stdout tape reads

31D streaming verification legitimately invokes `dd if="$dev" bs=...` without `of=`. The legacy mocks
in `run_real_e2e.sh`, `run_filemark_semantics.sh`, and the mock generated by `bric-vtl` assumed every
tape read had `of=DEST`. With an empty output path they attempted `cp SRC ""`, so streaming verification
received no payload. All mock read branches now implement both supported forms:

- `dd if=DEV of=DEST ...` -> copy selected tape file to DEST
- `dd if=DEV ...` -> emit selected tape file to stdout

`run_real_backend_mock.sh` already implemented both forms and remains the reference contract. A direct
VTL streaming verify was also exercised after the correction.

### 2. Structured-event assertions searched human stderr

`run_verify_failure_attribution.sh` correctly validated DB state but looked for
`SEGMENT_READBACK_FAILED`/`SEGMENT_VERIFY_FAILED` in `daemon.log`. Those are structured `bric_event`
records, not stderr contracts. Each `io`, `short`, and `corrupt` case now sets its own hermetic
`BRIC_LOG_DIR` and `BRIC_LOG_FALLBACK_DIR` and searches the structured `events/` trees.

### 3. WRITTEN crash regression assumed MainPID == generation

31D executes `one_pass` in a supervised child so it is not called under an `if/||/&&/!` context that
suppresses Bash errexit dynamically. The old recovery test killed only the daemon MainPID and also
required a human-log breadcrumb before accepting the DB `WRITTEN` state. Under the supervised topology
a pass child may legitimately remain alive after a MainPID-only signal. The regression now:

- synchronizes directly on the authoritative catalog state `WRITTEN`;
- kills the complete descendant tree before the MainPID, modelling systemd's control-group service
  termination;
- validates recovery through structured events and final DB/physical accounting rather than human-log
  placement.

This is a test-model correction; no production recovery/accounting code changes in 31D2.

### 4. Full-suite visual status

On interactive terminals the runner displays `OK` in ANSI green and `FAIL` in ANSI red. When stdout is
redirected, `TERM=dumb`, or `NO_COLOR` is set, the same labels are emitted without escape sequences.
The existing `[n/total]` progress contract is preserved.
