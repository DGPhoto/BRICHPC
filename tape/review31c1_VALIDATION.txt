BRIC Archive 2.0 Review 31C1 validation

Purpose
-------
Test-contract correction after the native Review 31C gate on supekgate04fl returned 58/61.
Production runtime is intentionally byte-identical to the published Review 31C tarball.
BRIC-FORMAT-V1 is unchanged.

Authoritative release gate
--------------------------
Run on supekgate04fl with the distribution sqlite3 CLI:

  sha256sum -c MANIFEST.sha256
  bash test/run_all_tests.sh --timeout 600

Required result:

  == 61 passed, 0 failed ==
  ✓ SUITE PASSED — software environment validated.

Why 31C1 exists
---------------
The three Review 31C failures were pre-existing test contracts that no longer represented the
31C behavior:

1. run_daemon_crash.sh stopped at a stale diagnostic-string assertion. This was more than cosmetic:
   everything after that assertion was skipped, including kill -9 with unresolved CLAIMED markers,
   acquisition of the singleton by a replacement daemon, recovery drain, CLOSED finalization, and
   PRIMARY/BACKUP verification. In the release that changed generation-safe singleton locking, the
   crash-recovery path therefore had no effective coverage. 31C1 removes the wording dependency and
   asserts the behavior through the completed crash/recovery lifecycle.

2. run_setup_e2e.sh still expected the pre-31C /opt/bric2-specific pgrep probe. 31C deliberately
   broadened the collision check after the real Review 30E daemon survived from an extracted tree.
   31C1 extracts the regex actually passed to pgrep -f and requires it to match the historical command:

     /opt/bric_archive_2_0_review30e_project_scoped_media_20260727/tape/bin/bric-tape-daemon --loop

   This tests the exact near-miss that motivated the change rather than a particular implementation
   string.

3. run_real_e2e.sh contained the historical mock command:

     rewind) echo 0>"$st";;

   Bash parses 0> as fd-0 redirection, so the mock position file remained empty. Review 31B1 did not
   verify the absolute landing and happened to tolerate the empty state. Review 31C correctly rejects
   an invalid/empty file number before reading. 31C1 fixes the mock and forces the first bsfm operation
   to fail, proving the fn=1 rewind-only fallback end-to-end. run_real_backend_mock.sh separately keeps
   the successful-but-wrong bsfm landing regression for fn>1.

Local validation used during construction
-----------------------------------------
A test-only sqlite3-compatible CLI compiled against the container libsqlite3 was used for iteration.
It is external to the release and is NOT an authoritative substitute for the distribution sqlite3 CLI.
With that harness the five tests touched by 31C1 passed:

  run_real_backend_mock.sh         PASS
  run_real_e2e.sh                  PASS
  run_daemon_crash.sh              PASS
  run_setup_e2e.sh                 PASS
  run_tape_singleton_migration.sh  PASS

The independent real-backend E2E forced bsfm failure on catalog file #1 and completed all five data
chunks, CLOSED finalization, 10/10 VERIFIED PRIMARY/BACKUP segments, five VERIFIED close artifacts,
and bit-identical DR recovery. The crash test completed the previously masked path through daemon
kill -9, replacement-daemon recovery, CLOSED finalization, and 32 VERIFIED copies.

Packaging invariants
--------------------
- cluster/, tape/, bric-update and bric-setup.sh must be byte-identical to the published 31C tarball.
- The only two files newly added to the 31C manifest set are:
    CHANGES_REVIEW31C1_TEST_CONTRACTS.md
    review31c1_VALIDATION.txt
- No echo N>"file" mock-position bug may remain under test/.
- Singleton tests assert behavior, not diagnostic wording.
- Before the definitive manifest is generated, RELEASE is timestamped after all intended tree edits;
  `find . -newer RELEASE -type f` must then return no files. This is the fixed contamination check for
  accidental runtime/test artifacts created after the tree was frozen.
- The final tarball must be extracted into an empty directory and pass sha256sum -c MANIFEST.sha256.

Status
------
31C1 is a candidate until the native supekgate04fl 61/61 gate passes. Do not install before that gate.
