Software Approach: Long-term Data Portability

The 5-Year Problem

Standard backup systems (like Bacula) store encryption keys on the backup server. If that server is gone, or the database is corrupted, or the software has moved on to incompatible versions - you've got tapes full of data you can't easily access.

That's not acceptable for research data.

Our Custom Solution: Simple & Portable

❌ Standard Approach

  • Complex backup software (Bacula, etc.)
  • Proprietary encryption formats
  • Keys tied to backup server
  • Vendor dependency for restores
  • Need full infrastructure to access data
  • Risk: lose access after 5-10 years

✓ BRIC Custom Approach

  • tar (unchanged since 1979)
  • Standard OpenSSL encryption
  • Each research group has own key
  • Zero vendor lock-in
  • Works on any LTO-9 drive worldwide
  • Data accessible for 30+ years

Technical Implementation

What we'll build:

  • Shell scripts to handle the archiving workflow
  • Database (SQLite or PostgreSQL) tracking:
    • Which files are on which tapes
    • Tape slot inventory
    • Encryption keys per research group
    • SHA256 checksums for data integrity
  • Simple restore interface for user requests

Complexity: This is not complex programming. Anyone comfortable with shell scripting can write and maintain this. Future maintainers can understand and modify it easily.

Researcher Data Ownership

When leaving the university, researchers receive:

  • Physical tapes (or copies)
  • Their encryption key
  • Simple README with extraction instructions

They can read their data on any LTO-9 compatible system worldwide using basic commands:

Load tape → Decrypt with key → Extract with tar

No dependency on BRIC infrastructure existing.

Data Security & Access Control

  • Per-group encryption: Each research group gets unique encryption key
  • Group isolation: Groups cannot access each other's archived data
  • Contained breaches: If a key is compromised, only that group's archives affected
  • Master key database: HPC admin maintains secure backup for recovery purposes only
  • Off-site option: Tapes can be stored at Iron Mountain or equivalent (35-45k DKK/year)

System Operations & Management

Day-to-Day Management

Operator: HPC team (David or designated technical staff)

Time commitment: 4-8 hours per week once operational

Required skills: Linux shell scripting, basic database management

Operational Responsibilities

Archive Requests

Process 1-2 requests per week

  • Stage data to disk cache
  • Calculate SHA256 checksums
  • Write to tape with encryption
  • Update database inventory
  • Send confirmation to researcher

Restore Requests

Handle 1-2 requests per month

  • Locate tapes in library
  • Restore to staging area
  • Verify checksums
  • Copy to user workspace
  • 24-48h typical turnaround

System Maintenance

Ongoing monitoring

  • Monitor library status
  • Manage tape rotation
  • Periodic integrity checks
  • Database backups
  • Documentation updates

Researcher Workflow

Archiving Data

Simple email request specifying:

  • Which project directories to archive
  • Any special organization preferences
  • Confirmation email address

Timeline: 1-3 weeks depending on data size and queue

Retrieving Data

Email request with:

  • What data needed (project name, dates, specific files)
  • Where to restore it (your project directory)

Timeline: 24-48 hours for most requests, several days for large multi-TB restores

Alternative: We can train one person from each group to perform restores independently

Taking Data When Leaving

Request your tapes via email, receive:

  • Your encryption key
  • Extraction instructions
  • Option to provide your own tapes for copy

Result: Full ownership of your research data permanently

Risk Management & Data Protection

Data Integrity

  • SHA256 checksums for every file
  • Verified at: staging, tape write, periodic audits
  • Database tracks all checksums
  • Dual copies: on-site + off-site (optional)

Hardware Failure

  • LTO-9 tapes: 30+ year shelf life
  • Two drives: operations continue if one fails
  • Backward compatible: reads LTO-7, LTO-8
  • Tapes readable in any LTO-9 drive worldwide

System Obsolescence

  • tar format: unchanged since 1979
  • Standard OpenSSL encryption
  • No proprietary formats
  • Simple codebase: easily maintainable

Institutional Changes

  • System operates independently of KU-IT
  • Minimal training for new operators
  • Researchers can take encrypted tapes
  • Full documentation provided

System Longevity

  • Expected operational life: 7-8 years (typical for enterprise tape systems)
  • Warranty period: 5 years standard
  • LTO-9 tapes: Rated for 30+ year shelf life
  • Backward compatibility: LTO-9 drives read LTO-7, LTO-8 tapes
